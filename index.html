Project 1 · G1 motion lab

What is being generated?

Movement, facing, and style become a short sequence of target G1 poses. The learned model predicts a continuation with root movement and joint rotations. A Go server streams it, and a browser draws an interpolated skeleton. The warm ghost is the target constraint; the mint skeleton is the generated result.

Measured on one machine

What we can claim—and what remains open

Established

  • SHA-256-verified G1 assets loaded through the original repository.
  • 15 styles and the 34-joint G1 skeleton reached the browser.
  • Movement changed generated motion; Windows start/stop launchers worked.
  • An eight-second probe received 168 poses over 162 server ticks.

Still to test

  • Sustained low latency and 50 Hz progress under realistic use.
  • Vulkan speed and peak VRAM on the 4 GB GPU.
  • SONIC/MuJoCo physical tracking and contact behavior.
  • Unreal integration, retargeting, and skinned-character quality.

A 461 ms first planner call and roughly 20 effective server ticks per wall-clock second in one sample are useful warnings against claiming game-ready real time. They are not a complete performance benchmark. GitHub Pages is a static learning site; the interactive model runs only on a local machine.

Where this work came from

The experiment began with Stefan 3D AI's video “Free and Local Real-Time AI Animation - NVIDIA MotionBricks.cpp”. The research is NVIDIA MotionBricks. The implementation and G1 assets used here are from localai-org/motion-bricks.cpp, studied at commit 2727a456. This independent repository contains educational notes, launch helpers, motion captures, reproducible experiments, interactive exhibits, and a recording; it does not redistribute the model or upstream source.
